# Builder Path voice guide

Every lesson, quiz question, quiz feedback line, build card, the handout, and the Cursor rules file in the starter repo follow these rules. Check new text against this list before you merge it.

## Rules

1. Short sentences and plain words. Address the learner as "you".
2. State the idea directly. Explain it with an example from bluehen-dssa.org, not a comparison to something else.
3. Use a metaphor only when the plain statement fails. At most one per lesson.
4. Prefer periods, commas and colons. At most one em-dash per lesson.
5. Bold a term once, where it is defined. Keep each stage's new words to a short list.
6. Use the "Do this now" pattern: one action, then how to confirm it worked.
7. Never write "don't use AI". Say what the learner must be able to do or explain themselves.
8. No filler and no hype. Leave out "simply", "just", "easy", "powerful" and "exciting".

## Sample at the target length and tone

> **Git** saves versions of your project. Each saved version is a **commit**. **GitHub** keeps a copy of your commits online.
>
> Do this now: open a new terminal and run `git --version`. You should see a version number.

## Quick check before you merge

- Can each sentence be read once and understood?
- Is every new term bolded once and defined in the same sentence?
- Did you count em-dashes? One per lesson at most.
- Does each "Do this now" say how the learner knows it worked?
- Would a first-year student with no coding background follow it?
